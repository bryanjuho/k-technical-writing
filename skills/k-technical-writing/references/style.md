# 문체 기준

국내 기술 문서, 상용 소프트웨어 변경이력 문체 기준

- ST: 지켜야하는 스타일 규칙
- D: 문서의 유형, 목적 또는 성격에 맞춰 사용자(@bryanjuho)가 직접 고른 항목들임. 참고사항이므로 유연하게 상황에 따라 접목해야 함
- 학습 규칙(LR)이 이 파일보다 우선

## ST

### ST-01. 문장은 합니다체

- 해라체(`-한다.`), 해요체(`-해요.`) 혼용 금지
- 주석, 커밋 본문, 변경이력 항목은 D-07, D-13, D-04 참고
- 예: 백업 파일은 7일 동안 보관합니다.

### ST-02. 제목, 표 칸, 목록 라벨, 변경이력 항목은 명사형

- 마침표 없음
- 표 칸에 `-음`, `-됨` 어미 대신 명사 사용
- 예: `## 백업 생성`, `| 상태 | 정지 |`, `- 보존 기간 변경`

### ST-03. 문장 끝 마침표

- 완결된 문장은 마침표, 명사형 항목은 마침표 없음
- 한 목록, 한 열 안 형식 통일

### ST-04. 영어 단어, 코드 뒤 조사는 붙여 씀

- 조사는 읽는 소리의 받침 기준 선택
- 예: `API를`, `` `helm`과 ``, `Pod를`, `` `config.yaml`을 ``

### ST-05. 이름은 원문, 일반 개념은 한국어

- 제품, 서비스, Kubernetes 리소스 종류는 원문 표기. 예: Argo CD, Deployment, Ingress
- 일반 개념은 한국어 또는 외래어 표기. 예: 클러스터, 노드, 인증서
- 처음 나오는 용어는 `한국어(English)` 병기. 예: 가용 영역(availability zone)
- 용어 표기는 [terminology.md](terminology.md) 참고

### ST-06. 리터럴은 백틱

- 명령, 경로, 파일 이름, 필드, 설정 키와 값, 상태 값, HTTP 상태 코드, 환경 변수
- 예: `` `READY`가 `True`이면 준비 완료 ``

### ST-07. 한 문서 안 용어 통일

- 같은 대상에 다른 표기 혼용 금지. 예: Pod와 파드 혼용 금지

### ST-08. 줄표(—) 금지

- 마침표로 끊거나 연결 어미로 연결. 짧은 덧붙임은 괄호

### ST-09. `우리`, `저희`, `여러분` 금지

- 시스템 동작은 시스템, 사람의 동작은 `사용자`, `운영자`가 주어. 뻔하면 생략

### ST-10. 근거 없는 평가어, 수치 없는 과장 금지

- 예: `효율적으로`, `안정적으로`, `원활하게`, `대폭`, `획기적으로`
- 실제 동작이나 측정값으로 대체

### ST-11. 문장 부호

- 여는 괄호 앞 붙임. 예: `보존 기간(일)`. 커밋 제목 끝 PR 번호(`(#123)`)만 예외
- 범위 물결표 붙임. 예: `1~365일`
- 숫자와 단위 붙임. 예: `256MB`, `30초`
- 천 단위 쉼표. 예: `1,000건`
- 느낌표 금지
