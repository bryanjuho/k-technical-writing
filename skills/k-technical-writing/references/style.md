# 문체 기준

국내 클라우드와 핀테크 개발자 문서 네 곳(NAVER Cloud, NHN Cloud, Kakao Cloud, Toss Payments)을 읽고 정리한 문체 규칙입니다. 출처와 인용은 [style-sources.md](style-sources.md)에 있습니다.

- ST: 확정 규칙입니다. 그대로 따릅니다.
- D: 결정 대기 항목입니다. 기본값을 따르되 사용자 피드백으로 바꿀 수 있습니다.
- 근거 표기: `4/4`는 네 곳 모두, `3/4`은 세 곳이 따르는 규칙입니다. `스킬 선택`은 기준 문서끼리 다르거나 근거가 약해 이 스킬이 정한 규칙입니다. `추정`은 기준 문서에 없는 문서 종류여서 가까운 형식에서 옮겨 온 규칙입니다.
- 기준 문서도 자기 규칙을 늘 지키지는 않습니다. 근거에는 대부분의 문서가 따르는 형태를 적었습니다.

학습 규칙(LR)이 이 파일보다 우선합니다.

## 문장 끝

### ST-01. 문장은 합니다체로 씁니다

본문, 런북, 참고와 주의 블록, PR 본문, 커밋 본문, 여러 줄 주석은 `-니다`로 끝냅니다. 해라체(`-한다.`, `-이다.`)와 해요체(`-해요.`)를 섞지 않습니다. 독자에게 권하는 `-하세요`는 ST-05에 따라 씁니다.

- 좋음: 백업 파일은 7일 동안 보관합니다.
- 나쁨: 백업 파일은 7일 동안 보관한다.
- 근거: 3/4. NAVER Cloud, NHN Cloud, Kakao Cloud의 본문은 모두 합니다체입니다. Toss Payments는 API 레퍼런스와 오류 메시지만 합니다체이고, 릴리스 노트와 일부 가이드는 해요체입니다.

### ST-02. 제목, 표 칸, 목록 라벨, 변경 기록 항목은 명사형으로 끝냅니다

문장이 아닌 자리는 명사나 `추가`, `변경`, `수정` 같은 동작 명사로 끝내고 마침표를 찍지 않습니다. API 필드 설명, 커밋 제목, 한 줄 주석, 알림 `summary`도 여기에 해당합니다.

- 좋음: `## 백업 보존 기간 변경`, `| 보존 기간 | 7일 |`, `- 보존 기간 7일 → 14일 변경`
- 나쁨: `## 백업 보존 기간을 변경합니다.`, `- 보존 기간을 14일로 늘렸다.`
- 설명이 긴 표 칸(항목과 설명 2열 표의 설명 칸)은 합니다체 문장으로 씁니다.
- 표 칸의 `-음`, `-됨` 명사형 어미(`서버가 정지 상태임`)는 쓰지 않고 명사로 끝냅니다(`서버 정지 상태`).
- 근거: 3/4(NAVER Cloud, NHN Cloud, Kakao Cloud). Toss Payments는 표 칸과 목록에도 문장을 씁니다. 긴 설명 칸의 문장은 NHN Cloud, Kakao Cloud, Toss Payments가 씁니다.

### ST-03. 문장이면 마침표를 찍고, 명사형이면 찍지 않습니다

목록 항목과 표 칸이 완전한 문장이면 마침표로 끝냅니다. 명사형 항목에는 마침표를 찍지 않습니다. 한 목록이나 한 열 안에서는 한 형식으로 맞춥니다. API 필드 설명 칸은 예외로, 명사구 아래에 제약 줄을 이어 쓸 수 있습니다(ST-23).

- 좋음: `- 삭제한 스냅샷은 복구할 수 없습니다.` / `- 스냅샷 자동 삭제`
- 나쁨: `- 삭제한 스냅샷은 복구할 수 없습니다` / `- 스냅샷 자동 삭제.`
- 근거: 4/4.

### ST-04. 절차의 각 단계에는 동작 하나만 씁니다

번호 목록 한 단계에는 동작 하나만 씁니다. 하위 항목에는 조건과 결과를 씁니다. 단계의 어미는 D-01을 따릅니다(기본값 `~합니다.`).

- 좋음: `1. **[백업 생성]** 버튼을 클릭합니다.`
- 나쁨: `1. 백업 생성 버튼을 클릭하고 이름을 입력한 뒤 저장한다.`
- 근거: 동작 하나는 스킬 선택입니다. 기준 문서 네 곳 모두 한 단계에 동작 두 개를 쓰는 경우가 있습니다.

### ST-05. 독자에게 권하는 문장에만 `-하세요`를 씁니다

다른 문서 참조, 주의 환기, 선택 동작에 `-하세요`를 씁니다. 다른 문서 참조의 어미는 D-08을 따릅니다. `-해 주십시오`, `-하시기 바랍니다`는 D-01과 D-08에서 고른 경우가 아니면 쓰지 않습니다.

- 좋음: 자세한 내용은 `[백업 복원](restore.md)`을 참고하세요.
- 나쁨: 자세한 내용은 백업 복원 문서를 참고해 주시기 바랍니다.
- 근거: 2/4(Kakao Cloud, Toss Payments). NAVER Cloud는 `-해 주십시오`, NHN Cloud는 `참고합니다`를 주로 씁니다. Kakao Cloud와 Toss Payments는 일반 지시에도 `-하세요`를 씁니다.

### ST-06. 가능, 필수, 권장, 시스템 동작을 정해진 형식으로 씁니다

| 뜻 | 형식 | 예 |
|---|---|---|
| 가능 | `~할 수 있습니다` | 볼륨은 최대 10개까지 연결할 수 있습니다. |
| 불가 | `~할 수 없습니다` | 삭제한 볼륨은 복구할 수 없습니다. |
| 필수 | `~해야 합니다` | 마운트 경로는 절대 경로로 지정해야 합니다. |
| 권장 | `~을 권장합니다` | 운영 환경에서는 복제본 2개 이상을 권장합니다. |
| 시스템 동작 | 피동형 `~됩니다` | 요청 한도를 넘으면 `429`가 반환됩니다. |
| 사용자 동작 | 능동형 | 설정 파일을 수정합니다. |

- 시스템이 항상 그렇게 동작하면 `~할 수 있습니다`를 쓰지 않고 단정합니다. 실제 선택지나 위험일 때만 씁니다.
- 문장 서술어로 `~가 가능합니다`를 쓰지 않고 `~할 수 있습니다`를 씁니다. 표 칸과 변경 기록 항목의 `~ 가능`은 괜찮습니다.
- 근거: 형식은 4/4. `~가 가능합니다`를 쓰지 않는 것은 스킬 선택입니다(NAVER Cloud와 NHN Cloud는 씁니다).

### ST-07. 조건과 목록 도입은 정해진 표현을 씁니다

- 조건: `~하는 경우`, `~할 때`, `~ 시`(`생성 시`처럼 띄어 씁니다)
- 목록이나 표 앞: `~은 다음과 같습니다.`
- 근거: 3/4(NAVER Cloud, NHN Cloud, Kakao Cloud). Toss Payments는 `아래와 같습니다`와 `~할 때`를 주로 씁니다.

## 단어

### ST-08. 영어 단어와 코드 뒤 조사는 붙이고, 발음에 맞춥니다

조사는 영어를 읽은 소리의 받침 유무로 고릅니다. 괄호로 덧붙인 풀이는 조사 선택에 영향을 주지 않습니다.

- 좋음: `API를`, `` `helm`과 ``, `Pod를`, `Ingress를`, `VPC(Virtual Private Cloud)를`, `` `config.yaml`을 ``
- 나쁨: `API 를`, `` `helm` 과 ``, `Ingress을`
- 근거: 4/4. 띄운 예와 받침을 잘못 고른 예(`` `issueNumber`은 ``)도 드물게 있지만 실수로 봅니다.

### ST-09. 이름은 영어로, 일반 개념은 한국어로 씁니다

- 제품, 서비스, 기능 이름과 Kubernetes 리소스 종류는 영어로 씁니다. 예: Kubernetes Engine, Deployment, Ingress, Argo CD
- 일반 개념은 외래어 표기나 한국어 용어를 씁니다. 예: 클러스터, 노드, 네임스페이스, 스토리지, 인증서
- 같은 단어도 이름일 때와 개념일 때를 구분합니다. 예: Load Balancer 서비스에서 로드 밸런서를 생성합니다.
- 처음 나오는 용어는 `한국어(English)`로 쓰고 이후에는 한국어만 씁니다. 괄호 앞은 띄우지 않습니다. 예: 가용 영역(availability zone)
- 약어는 `풀이(약어)`로 처음 한 번 씁니다. 예: 역할 기반 접근 제어(RBAC)
- 용어 목록은 [terminology.md](terminology.md)에 있습니다.
- 근거: 4/4. 반대 순서(`Anti-Affinity(분산 배치)`, `AZ(가용 영역)`)도 NAVER Cloud와 Kakao Cloud에 있습니다.

### ST-10. 리터럴은 백틱으로 감쌉니다

명령, 경로, 파일 이름, 필드와 파라미터, 설정 키와 값, 상태 값, HTTP 상태 코드, 환경 변수를 백틱으로 감쌉니다. 영어 열거 값에는 필요하면 괄호로 뜻을 덧붙입니다.

- 좋음: `` `READY`가 `True`이면 준비가 끝난 것입니다. ``, `` `Pending`(대기) ``
- 나쁨: `READY가 True이면 준비가 끝난 것입니다.`
- 근거: 3/4(NHN Cloud, Kakao Cloud, Toss Payments). NAVER Cloud는 가이드에서 백틱과 작은따옴표를 섞어 씁니다.

### ST-11. 화면 요소는 굵게 씁니다

- 메뉴 경로는 항목마다 굵게 쓰고 ` > `로 잇습니다. 예: **Compute** > **Server** 메뉴로 이동합니다.
- 버튼은 굵게 쓰고 대괄호로 감싼 뒤 `버튼`을 붙입니다. 예: **[생성]** 버튼을 클릭합니다.
- 탭, 옵션, 상태 이름은 굵게 씁니다. 예: **운영 중** 상태
- 근거: 굵게는 4/4. 세부 형식은 스킬 선택입니다(D-09). 항목별 굵게와 버튼 대괄호는 NAVER Cloud 형식입니다. NHN Cloud와 Toss Payments는 경로 전체를 한 번에 굵게 쓰고, Kakao Cloud는 버튼을 굵게 쓰지 않습니다.

### ST-12. 주어는 시스템이나 사용자로 씁니다

`우리`, `저희`, `여러분`을 쓰지 않습니다. 시스템 동작은 시스템을, 사람의 동작은 `사용자`나 `운영자`를 주어로 씁니다. 주어가 뻔하면 생략합니다.

- 근거: 4/4.

## 문장 부호와 숫자

### ST-13. 값 변화는 표와 항목에서 화살표로, 문장에서는 `A에서 B로`로 씁니다

- 변경 기록 항목, 표, 커밋 제목: 보존 기간 `7d` → `14d` 변경
- 문장: 보존 기간을 `7d`에서 `14d`로 변경했습니다.
- 바뀌는 값이 여러 개면 `변경 전:`, `변경 후:` 하위 항목을 씁니다.
- 근거: 스킬 선택. 화살표는 NHN Cloud(버전 변경), Kakao Cloud와 Toss Payments(일부 항목과 제목)가 씁니다. `A에서 B로`는 NAVER Cloud, Kakao Cloud, Toss Payments가 씁니다. `변경 전/후`는 NAVER Cloud가 씁니다.

### ST-14. 줄표(—)를 쓰지 않습니다

문장을 줄표로 잇지 않습니다. 마침표로 끊거나 연결 어미로 잇습니다. 짧은 덧붙임은 괄호에 넣습니다.

- 좋음: 기본값을 비워 둡니다. 값이 비어 있으면 키를 생성하지 않습니다.
- 나쁨: 기본값을 비워 둔다 — 값이 비어 있으면 키를 만들지 않는다.
- 근거: 3/4(NAVER Cloud, NHN Cloud, Kakao Cloud는 0회). Toss Payments는 SDK 레퍼런스에서만 드물게 씁니다.

### ST-15. 문장 부호 세부 규칙

- 콜론은 앞을 붙이고 뒤를 한 칸 띄웁니다. 라벨과 값, 열거 값 설명에만 씁니다. 예: `` `ACTIVE`: 사용 중인 상태 ``
- 여는 괄호 앞은 띄우지 않습니다. 예: `가용 영역(AZ)`. 커밋 제목 끝의 PR 번호(`(#123)`)는 예외로 한 칸 띄웁니다.
- 범위는 물결표를 띄우지 않고 씁니다. 예: `3~15자`, `1~365일`
- 천 단위에는 쉼표를 씁니다. 예: `1,000건`
- 숫자와 단위는 붙여 씁니다. 예: `256MB`, `30초`, `10개`
- 따옴표는 화면 문구나 사용자가 입력하는 값에만 씁니다. 코드 값은 백틱으로 감쌉니다.
- 근거: 대부분 4/4입니다. 물결표와 괄호 앞을 띄운 예(`10GB ~ 20TB`, `` `SSD` (기본값) ``)도 기준 문서에 섞여 있습니다. 가운뎃점은 D-02를 참고하세요.

### ST-16. 날짜와 시각은 한국어 형식으로 씁니다

- 본문: `2026년 9월 17일`
- 변경 기록 날짜 제목: D-03
- 시각: `14:00(KST)`. 시간대를 밝힙니다(스킬 선택).
- 파일 이름, 메타데이터 줄, 코드 안 값처럼 기계가 읽는 자리에는 `2026-09-17`을 씁니다.
- 근거: 본문 날짜는 NAVER Cloud, Kakao Cloud가 씁니다.

## 구조

### ST-17. 제목은 명사형이며 마침표를 찍지 않습니다

- 좋음: `## 백업 생성`, `## 사전 준비`, `### 1. 이미지 선택`
- 나쁨: `## 백업을 생성하는 방법에 대하여`, `## 백업 생성.`
- 문제 해결 항목은 `~하는 경우`로 끝냅니다. 예: `### 마운트 옵션이 잘못된 경우`
- 근거: 3/4(NAVER Cloud, NHN Cloud, Kakao Cloud). Toss Payments 가이드는 `-하기`, `-하세요`, 질문형 제목을 씁니다.

### ST-18. 문서 첫머리에 범위를 한두 문장으로 밝힙니다

H1 바로 아래에 `~하는 방법을 설명합니다.`나 `~을 안내합니다.`처럼 이 문서가 다루는 범위를 씁니다.

- 좋음: `# 백업 복원` 아래 `스냅샷에서 데이터베이스를 복원하는 방법을 설명합니다.`
- 근거: NAVER Cloud, Toss Payments는 모든 문서에, Kakao Cloud와 NHN Cloud는 일부 문서에 둡니다.

### ST-19. 참고와 주의는 라벨이 있는 인용 블록으로 씁니다

```markdown
> **참고**
> 스냅샷은 같은 리전에서만 복원할 수 있습니다.

> **주의**
> 볼륨을 삭제하면 데이터를 복구할 수 없습니다.
```

- `주의`는 데이터 손실, 서비스 중단, 비용 발생, 되돌릴 수 없는 작업에만 씁니다. 나머지는 `참고`입니다.
- 블록 안은 합니다체 문장입니다.
- 근거: 라벨 블록은 4/4. 라벨 이름과 형식은 다릅니다. NAVER Cloud는 `참고`와 `주의`, NHN Cloud는 `[참고]`와 `[주의]`, Kakao Cloud는 `안내`와 `주의`, Toss Payments는 `참고`와 `경고`를 씁니다. `주의`의 범위를 좁힌 것은 스킬 선택입니다.

### ST-20. 명령 블록 앞에는 목적을, 뒤에는 정상 결과를 씁니다

- 앞: `다음 명령으로 Pod 상태를 확인합니다.`
- 뒤: `` 정상이면 `STATUS`가 `Running`으로 표시됩니다. ``
- 코드 블록에는 언어 태그를 붙입니다.
- 근거: 목적 문장은 NAVER Cloud, NHN Cloud, Kakao Cloud. 정상 결과 문장은 Kakao Cloud. 언어 태그는 Kakao Cloud, Toss Payments(NAVER Cloud와 NHN Cloud 가이드에는 없음).

### ST-21. 한 문장에는 사실 하나를 씁니다

근거 없는 평가어(`효율적으로`, `안정적으로`, `원활하게`)와 수치 없는 과장(`대폭`, `획기적으로`)을 쓰지 않습니다. 실제 동작이나 측정값을 씁니다. 자세한 패턴은 [ai-patterns.md](ai-patterns.md)에 있습니다.

- 근거: 스킬 선택. 기준 문서의 절차와 레퍼런스는 대체로 따르지만, 네 곳 모두 서비스 소개 페이지에서는 평가어를 씁니다.

## 변경 기록과 API 레퍼런스

### ST-22. 변경 기록 항목은 명사형 한 줄로 씁니다

- 날짜 제목(D-03) 아래 분류(D-10)를 두고, 항목은 `<대상> <동작 명사>`로 씁니다. 과거 시제와 마침표를 쓰지 않습니다.
- 버그 수정은 `<조건> 시 <증상>하던 문제 수정`으로 씁니다.
- 기능이나 설정을 없앨 때는 날짜와 대체 수단을 함께 씁니다.
- 사용자가 조치해야 하는 변경은 하위 항목에 씁니다(D-11).
- 적용 범위와 조건은 괄호에 씁니다. 예: `(production 한정)`
- 자세한 템플릿은 [doc-types.md](doc-types.md#변경-기록)에 있습니다.
- 근거: 명사형 항목은 3/4(NAVER Cloud, NHN Cloud, Kakao Cloud API 변경 사항). Kakao Cloud 서비스 릴리스 노트와 Toss Payments는 제목 아래 문장을 씁니다. `~하던 문제 수정`은 NAVER Cloud와 NHN Cloud가 씁니다. 대체 수단을 함께 쓰는 형식은 Toss Payments에서 가져왔습니다.

### ST-23. API 레퍼런스는 요약 문장, 명사구 필드 설명, 명사형 제약 줄로 씁니다

- 엔드포인트 요약: 합니다체 한 문장. 예: `백업을 생성합니다.`
- 필드 설명: 명사구. 예: `백업 보존 기간(일)`
- 불리언 필드: `~ 여부`. 예: `자동 삭제 사용 여부`
- 제약과 기본값: 필드 설명 아래 명사형 줄(D-12). 예: `1~365 입력 가능`, ``기본값: `7` ``
- 응답: `성공하면 ~ 객체를 반환합니다.`
- 오류 설명: 합니다체 문장. 예: `같은 이름의 백업이 이미 있습니다.`
- 근거: 요약 문장은 4/4. 명사구 필드 설명과 명사형 제약 줄은 3/4(NAVER Cloud, NHN Cloud, Kakao Cloud). Toss Payments는 `명사구 + 입니다.`와 `최대 길이는 200자입니다.` 같은 문장을 쓰고, 응답은 `~가 돌아옵니다`로 씁니다. 오류 설명 문장은 Kakao Cloud, Toss Payments 형식입니다(NAVER Cloud는 명사형).
