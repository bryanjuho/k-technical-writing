# 문서 종류별 템플릿

문서 종류마다 쓰는 형식을 정리했습니다. 문장 규칙은 [style.md](style.md)를 따릅니다. `추정`이라고 표시한 템플릿은 기준 문서에 없는 종류여서 가장 가까운 형식(릴리즈 노트, 가이드, 문제 해결 문서)에서 옮겨 왔습니다. 기준 문서끼리 형식이 다른 부분은 [style.md](style.md)의 선택 예시를 기본값으로 씁니다. 템플릿도 예시이므로 문서에 맞지 않는 절은 빼거나 바꿉니다.

## 가이드, README

```markdown
# 백업 설정

데이터베이스 자동 백업을 설정하는 방법을 설명합니다.

## 개요

자동 백업은 매일 설정한 시각에 전체 백업을 생성합니다. 백업 파일은 오브젝트 스토리지에 보관됩니다.

## 사전 준비

- 데이터베이스 관리자 권한
- 백업을 저장할 버킷

## 백업 설정 방법

자동 백업을 설정하는 방법은 다음과 같습니다.

1. **Database** > **Backup** 메뉴로 이동합니다.
2. **[백업 설정]** 버튼을 클릭합니다.
3. **보존 기간**에 `7`을 입력합니다.
   - 보존 기간은 1~365일 사이로 설정할 수 있습니다.
4. **[저장]** 버튼을 클릭합니다.

> **참고**
> 백업은 설정한 다음 날부터 생성됩니다.

## 관련 문서

- [백업 복원](restore.md)
```

- H1은 기능이나 작업 이름입니다. H1 아래 한두 문장으로 범위를 밝힙니다(ST-18).
- 개념 설명, 사전 준비, 절차, 참고 순서로 씁니다.
- 표의 설명 칸은 짧으면 명사형, 길면 합니다체 문장입니다. 한 열 안에서는 한 형식으로 맞춥니다.

## 런북

추정. 가이드의 절차와 문제 해결 문서 형식에서 옮겨 왔습니다.

```markdown
# 디스크 사용률 경보 대응

노드 디스크 사용률 경보가 발생했을 때 원인을 찾고 공간을 확보하는 방법을 설명합니다.

| 항목 | 내용 |
|---|---|
| 적용 대상 | 모든 워커 노드 |
| 필요 권한 | 클러스터 관리자 |
| 관련 경보 | `NodeDiskUsageHigh` |
| 마지막 확인 | 2026-11-09 |

## 증상

- `NodeDiskUsageHigh` 경보 발생
- 노드의 Pod가 `Evicted` 상태로 종료

## 원인 확인

1. 사용률이 높은 노드를 확인합니다.

   ```bash
   kubectl describe node <노드 이름>
   ```

   정상일 경우 `Conditions`의 `DiskPressure`는 `False`로 표시됩니다. `True`이면 디스크가 부족한 노드입니다.

2. 노드에 접속해 큰 디렉터리를 찾습니다.

   ```bash
   sudo du -xh /var/lib --max-depth=2 | sort -rh | head
   ```

## 조치

> **주의**
> 컨테이너 이미지를 삭제하면 다음 배포 시 이미지를 다시 받습니다. 배포가 몰리는 시간을 피하세요.

1. 사용하지 않는 이미지를 삭제합니다.

   ```bash
   sudo crictl rmi --prune
   ```

## 확인

- 디스크 사용률 80% 미만
- 경보 해제

## 되돌리기

이미지 삭제는 되돌릴 수 없습니다. 필요한 이미지는 레지스트리에서 다시 받습니다.

## 문제 해결

### 공간이 확보되지 않는 경우

삭제된 파일을 프로세스가 계속 열고 있을 수 있습니다. `lsof +L1`로 확인합니다.
```

- 첫 표에 적용 대상, 권한, 관련 경보, 마지막 확인 날짜를 씁니다.
- 명령마다 앞에 목적, 뒤에 정상 결과를 씁니다(ST-20).
- 되돌릴 수 없는 단계 앞에는 `주의` 블록을 둡니다(ST-19).
- 문제 해결 항목 제목은 `~하는 경우`로 끝냅니다.

## 장애 기록

추정. 가이드와 릴리즈 노트 형식에서 옮겨 왔습니다.

```markdown
# 2026-08-04 인증서 자동 갱신 실패

| 항목 | 내용 |
|---|---|
| 상태 | 해결 |
| 영향 | 내부 대시보드 접속 2시간 중단 |
| 발생 시각 | 2026년 8월 4일 09:10(KST) |
| 해결 시각 | 2026년 8월 4일 11:05(KST) |

## 요약

TLS 인증서 자동 갱신이 DNS 검증 단계에서 실패해 인증서가 만료되었습니다.

## 타임라인

| 시각(KST) | 내용 |
|---|---|
| 09:10 | 인증서 만료, 대시보드 접속 오류 발생 |
| 09:40 | DNS API 토큰 만료 확인 |
| 11:05 | 토큰 교체 후 인증서 재발급 완료 |

## 원인

## 조치

## 재발 방지

- DNS API 토큰 만료 30일 전 알림 추가
```

- 상태 값은 `조사 중`, `완화`, `해결`, `종결` 중 하나입니다.
- 본문은 합니다체, 타임라인 칸은 명사형입니다.
- 추정과 확인한 사실을 구분합니다. 확인하지 못한 내용에는 `(확인 필요)`를 붙입니다.

## 변경이력

CHANGELOG와 릴리즈 노트에 씁니다.

```markdown
## 2026. 11. 9.

### 추가

- 데이터베이스 자동 백업 기능 추가
- 백업 실패 알림 추가(production 한정)

### 변경

- 백업 보존 기간 `7d` → `14d` 변경
- 기본 이미지 태그 `latest` → `sha-1a2b3c4` 고정

### 수정

- 백업 파일 이름에 시간대가 빠지던 문제 수정
- 노드 재시작 시 마운트가 해제되던 문제 수정

### 종료

- `backup.legacy` 설정 지원 종료
  - 2026년 12월 1일부터 이 설정은 무시됩니다. `backup.schedule`을 사용하세요.

### 제거

- 사용하지 않는 `backup.compress` 설정 제거
```

- 날짜 제목은 최신순으로 둡니다(D-03).
- 분류는 `추가`, `변경`, `개선`, `수정`, `제거`, `종료`, `보안` 중 해당하는 것만 둡니다(D-10). 날짜마다 같은 분류를 한 번만 씁니다.
- `종료`는 기한을 두고 지원을 끝내는 경우, `제거`는 바로 없애는 경우에 씁니다.
- 항목은 `<대상> <동작 명사>` 한 줄이며 마침표가 없습니다(ST-22).
- 버그 수정은 `<조건> 시 <증상>하던 문제 수정`입니다.
- 사용자가 조치해야 하는 내용, 영향 범위, 대체 수단은 하위 항목에 합니다체 문장으로 씁니다.
- 조사 과정, 설계 이유, 측정 기록은 변경이력에 쓰지 않습니다. PR 본문이나 설계 문서에 쓰고 링크를 겁니다.

## API 레퍼런스

```markdown
### 백업 생성

`POST /v1/backups`

백업을 생성합니다.

#### 요청 본문

| 이름 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `name` | string | O | 백업 이름 |
| `retentionDays` | integer | - | 백업 보존 기간(일)<br>- 1~365 입력<br>- 미입력 시 기본값 `7` |
| `encrypted` | boolean | - | 암호화 사용 여부 |

#### 응답

요청이 성공적으로 처리된 경우, 생성된 `Backup` 객체가 반환됩니다.

#### 오류

| 코드 | 설명 |
|---|---|
| `400` | 요청 본문 형식이 올바르지 않습니다. |
| `409` | 같은 이름의 백업이 이미 있습니다. |
```

- 엔드포인트 요약은 합니다체 한 문장입니다.
- 필드 설명은 명사구로 쓰고, 제약과 기본값은 아래에 명사형 줄로 씁니다(ST-23, D-12). 표 안에서는 `<br>`로 줄을 나눕니다. 줄을 나누기 어려우면 `백업 보존 기간(일). 1~365 사이 값이어야 합니다.`처럼 문장으로 씁니다.
- 응답은 조건절로 시작하는 피동문입니다(D-14).
- 열거 값은 `` `ACTIVE`: 사용 중인 상태 ``처럼 콜론으로 설명합니다.
- 오류 설명은 합니다체 문장입니다.

## 커밋 메시지

추정. 변경이력 항목 형식에서 옮겨 왔습니다.

```text
fix(backup): 노드 재시작 시 마운트가 해제되던 문제 수정

- 노드 재시작 후 백업 볼륨 자동 마운트 실패
- `/etc/fstab`에 백업 볼륨 항목 추가
- production 노드 미적용
```

- 제목: `type(scope): <명사형 요약>`. 마침표를 찍지 않고 50자 안팎으로 씁니다(D-06).
- 본문: 마침표 없는 명사형 글머리 목록(D-13). 증상이나 배경, 변경 내용, 적용 상태 순서로 씁니다. 값 변경은 `` `A` → `B` 변경``으로 씁니다.
- 파일별 변경은 `- 경로: 변경 내용` 형식으로 씁니다.
- 설계 이유처럼 목록으로 나누기 어려운 설명은 합니다체 문단으로 씁니다.

## 변경 사항

- `docs/backup.md`: 보존 기간 설명 수정

## 확인 방법

- `helm template` 결과에서 `retention: 14d` 확인

## 적용 순서

1. 이 PR을 병합합니다.
2. 백업 CronJob이 다음 실행 시 새 값을 사용하는지 확인합니다.

## 되돌리기

이 PR을 되돌리면 다음 실행부터 7일 보존으로 돌아갑니다.
```

- 절 제목은 명사형, 본문은 합니다체, 목록은 명사형입니다.
- 실행한 명령과 결과는 실제로 실행한 것만 씁니다.

## 코드와 설정 주석

추정. 기준 문서의 코드 블록 주석에서 옮겨 왔습니다.

```yaml
# 노드당 Pod 1개만 배치
podAntiAffinity: ...

# 보존 기간을 늘리면 버킷 용량도 함께 늘려야 함
# 14일 기준 약 2TB 필요
retention: 14d
```

- 주석은 명사형으로 끝내고 마침표를 찍지 않습니다(D-07). 이유를 쓸 때는 원인과 결과를 한 문장으로 잇고 `~됨`, `~함`으로 끝냅니다.
- 문서처럼 긴 설명(파일 머리 주석, docstring)은 합니다체 문장도 씁니다.
- 코드를 읽으면 알 수 있는 동작은 쓰지 않습니다. 이유, 예외, 함께 바꿔야 하는 곳을 씁니다.
- 주석 안에서는 굵게(`**`)를 쓰지 않습니다.

## 알림 텍스트

추정. 릴리즈 노트 항목과 가이드 문장 형식에서 옮겨 왔습니다.

```yaml
annotations:
  summary: "{{ $labels.instance }} 디스크 사용률 90% 초과"
  description: >-
    {{ $labels.instance }}의 디스크 사용률이 10분 동안 90%를 넘었습니다.
    공간이 부족하면 새 Pod를 배치할 수 없습니다.
    대응 방법은 런북을 참고하세요.
  runbook_url: https://example.com/runbooks/node-disk-usage
```

- `summary`는 명사형이며 마침표가 없습니다. 대상과 상태를 씁니다.
- `description`은 합니다체 문장입니다. 상태, 영향, 대응 순서로 씁니다.
- 템플릿 변수 뒤 조사는 대표 값의 발음에 맞춥니다. 값을 알 수 없으면 조사가 필요 없는 형식(`{{ $labels.instance }} 디스크 사용률`)으로 씁니다.
