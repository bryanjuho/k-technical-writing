## 가이드, README

```markdown
# 백업 설정

데이터베이스 자동 백업을 설정하는 방법을 설명합니다.

## 사전 준비

- 데이터베이스 관리자 권한
- 백업을 저장할 버킷

## 백업 설정

1. **Database** > **Backup** 메뉴로 이동합니다.
2. **[백업 설정]** 버튼을 클릭합니다.
3. **보존 기간**에 `7`을 입력합니다.
   - 보존 기간은 1~365일 사이로 설정할 수 있습니다.
4. **[저장]** 버튼을 클릭합니다.

> **참고**
> 백업은 설정한 다음 날부터 생성됩니다.

## 관련 문서

- [백업 복원](restore.md)
```

## 런북

```markdown
# 디스크 사용률 경보 대응

노드 디스크 사용률 경보가 발생했을 때 공간을 확보하는 방법을 설명합니다.

| 항목 | 내용 |
|---|---|
| 적용 대상 | 모든 워커 노드 |
| 필요 권한 | 클러스터 관리자 |
| 관련 경보 | `NodeDiskUsageHigh` |
| 마지막 확인 | 2026-11-09 |

## 원인 확인

1. 디스크가 부족한 노드를 확인합니다.

   ```bash
   kubectl describe node <노드 이름>
   ```

   정상일 경우 `Conditions`의 `DiskPressure`는 `False`로 표시됩니다.

## 조치

> **주의**
> 이미지를 삭제하면 다음 배포 시 이미지를 다시 받습니다.

1. 사용하지 않는 이미지를 삭제합니다.

   ```bash
   sudo crictl rmi --prune
   ```

## 확인

- 디스크 사용률 80% 미만
- 경보 해제

## 문제 해결

### 공간이 확보되지 않는 경우

삭제된 파일을 프로세스가 열고 있을 수 있습니다. `lsof +L1`로 확인합니다.
```

## 장애 기록

```markdown
# 2026-08-04 인증서 자동 갱신 실패

| 항목 | 내용 |
|---|---|
| 상태 | 해결 |
| 영향 | 내부 대시보드 접속 2시간 중단 |
| 발생 시각 | 2026년 8월 4일 09:10(KST) |
| 해결 시각 | 2026년 8월 4일 11:05(KST) |

## 요약

DNS 검증 단계에서 인증서 자동 갱신이 실패해 인증서가 만료되었습니다.

## 타임라인

| 시각(KST) | 내용 |
|---|---|
| 09:10 | 인증서 만료, 대시보드 접속 오류 발생 |
| 09:40 | DNS API 토큰 만료 확인 |
| 11:05 | 토큰 교체 후 인증서 재발급 |

## 원인

## 조치

## 재발 방지

- DNS API 토큰 만료 30일 전 알림 추가
```

- 상태: `조사 중`, `완화`, `해결`, `종결`
- 확인하지 못한 내용은 `(확인 필요)` 표시

## 변경이력

```markdown
## 2026. 11. 9.

### 추가

- 데이터베이스 자동 백업 추가

### 변경

- 백업 보존 기간 `7d` → `14d` 변경

### 수정

- 노드 재시작 시 백업 볼륨이 마운트되지 않던 문제 수정

### 종료

- `backup.legacy` 설정 지원 종료
  - 2026년 12월 1일부터 이 설정은 무시됩니다. `backup.schedule`을 사용하세요.

### 제거

- `backup.compress` 설정 제거
```

- 날짜 최신순
- `종료`는 기한을 두고 지원 종료, `제거`는 즉시 삭제
- 조사 과정, 설계 이유는 PR이나 설계 문서에 작성

## API 레퍼런스

```markdown
### 백업 생성

`POST /v1/backups`

백업을 생성합니다.

| 이름 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `name` | string | O | 백업 이름 |
| `retentionDays` | integer | - | 백업 보존 기간(일)<br>- 1~365 입력<br>- 미입력 시 기본값 `7` |
| `encrypted` | boolean | - | 암호화 사용 여부 |

요청이 성공적으로 처리된 경우, 생성된 `Backup` 객체가 반환됩니다.

| 코드 | 설명 |
|---|---|
| `400` | 요청 본문 형식이 올바르지 않습니다. |
| `409` | 같은 이름의 백업이 이미 있습니다. |
```

- 열거 값은 `` `ACTIVE`: 사용 중인 상태 `` 형식

## 커밋 메시지

```text
fix(backup): 노드 재시작 시 마운트가 해제되던 문제 수정

- 노드 재시작 후 백업 볼륨 자동 마운트 실패
- `/etc/fstab`에 백업 볼륨 항목 추가
- production 노드 미적용
```

- 제목 50자 안팎
- 목록으로 나누기 어려운 설명은 합니다체 문단

## PR 본문

```markdown
## 요약

백업 보존 기간을 7일에서 14일로 늘립니다.

## 변경 사항

- `backup/values.yaml`: `retention` `7d` → `14d` 변경

## 확인 방법

- `helm template` 결과에서 `retention: 14d` 확인

## 되돌리기

이 PR을 되돌리면 다음 실행부터 7일 보존으로 돌아갑니다.
```

- 실행한 명령과 결과는 실제로 실행한 것만 작성

## 주석

```yaml
# 노드당 Pod 1개만 배치
podAntiAffinity: ...

# 보존 기간을 늘리면 버킷 용량도 함께 늘려야 함
retention: 14d
```

- 코드로 알 수 있는 동작 대신 이유, 예외, 함께 바꿀 곳 작성
- 주석 안 굵게 금지
- 긴 docstring은 합니다체 가능
